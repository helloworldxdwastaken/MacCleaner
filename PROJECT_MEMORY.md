## Architecture
- UI (2026-09-19 v3): full-app WALLPAPER system — `body[data-pagebg="<view>"]::before` swaps to a per-section generated gradient JPG (`public/assets/bg-<view>.jpg`, 9 views) set by `switchView` via `TINTED_VIEWS`; on tinted pages text is white (scoped `--text-*`/`--surface-*` var overrides on the view + `body[data-pagebg] .sidebar` dark frosted glass with `color: var(--text-1)` re-resolve) and cards are 10%-white frosted glass. Non-tinted pages keep the mint-white blob backdrop (`--canvas-base: #f0f5f2`). Dashboard: naked centered section icon (icon-dashboard-256) + title/tagline/identity/green CTA, cards in 3 columns (Disk usage · Temp&fans · Lifetime impact); Quick Actions/Storage Trend/Recent-activity cards REMOVED (trend JS deleted). White 3D mini-icons (`icon-white-*`) on card headers. Theme locked light, toggle removed. hiddenInset title bar + `.titlebar-drag`. Per-launch token + hostGuard unchanged; assets under /assets are token-free (express.static).
- UI is macOS Liquid Glass (Tahoe-style, restored 2026-07-25 after an 8-bit/16-bit retro detour): the `.vibrant` layer in `public/index.html` + Electron `vibrancy: 'under-window'` are the glass path — keep them. Radii `--r-lg/md/sm` = 22/14/10px. The floating header island was removed: theme toggle + scan spinner live in `.side-footer` next to Preferences. A backup of the 16-bit retro version is at `/tmp/mccleaner-retro-index.html.bak` (not in git — retro work was never committed).
- All `/api` routes require a per-launch random token (`src/middleware/auth.ts`): `X-MacCleaner-Token`/`Bearer` header via `createTokenGuard` (global default — headers ONLY since 2026-09-19); `?token=` query is additionally accepted ONLY on raw-browser-client routes via the route-scoped `createQueryTokenGuard` export (EventSource SSE + app-icon `<img>`); those routes must be registered BEFORE the global `app.use('/api', createTokenGuard(token))` or the header-only guard 401s query-only clients first. Token is injected into the served index.html as `window.MACCLEANER_TOKEN`, never persisted to disk.
- Global `hostGuard` (`src/middleware/auth.ts`) rejects missing/non-loopback Host headers (DNS-rebinding defense) — it must stay mounted ahead of every route, including `GET /` (which dispenses the token).
- `DELETE /api/files` only authorizes paths inside scans with status `complete` (`requireInsideScanRoot`, `src/middleware/pathGuard.ts`); delete targets are realpath-checked at the parent level so symlinks can't escape the scanned tree.
- Scan roots are realpath-resolved in `startScan` (`src/services/diskScanner.ts`); `/` and `/System/Volumes/Data` are rejected (`assertScanRootAllowed`).
- Completed scan trees are pruned to ~500k nodes; dirs with dropped children carry `truncated: true` and must be treated as non-empty by aggregations.

## Gotchas / lessons learned
- `vm_stat -q` is an illegal option on current macOS (26.3) — parse plain `vm_stat` for page accounting (systemStats.ts does; arch fallback page size 16384 on arm64).
- `storage.ts` `withFileLock` serializes read→mutate→write per file — never call `writeJsonFile` inside its callback (deadlock). Corrupt/unreadable app-data JSON files are quarantined as `<name>.corrupt-<ts>` (bytes preserved) and that lock cycle SKIPS the write (`FileLockContext.skipWrite`); `readJsonFile` falls back only on ENOENT. settings.ts mutations go through `persistLocked` (rebuild-from-disk inside the lock, retry once after quarantine); PATCH/PUT must never read-modify-write outside the lock.
- Path blocklist (`src/utils/pathSanitizer.ts`) is lexical + case-insensitive; macOS symlinks need both spellings blocked (`/etc` + `/private/etc`, `/var/db` + `/private/var/db`). Do NOT block all of `/var` — `/var/folders` holds user temp/caches, a legitimate clean target.
- Login items come from TWO sources: System Events (classic "Open at Login", toggleable, needs Automation consent) and `sfltool dumpbtm` (modern BTM/SMAppService background items — Adobe CC & co., read-only, macOS owns the switch, consent-free). Both are merged in `src/services/maintenance.ts` `listLoginItems`; BTM records have `kind: 'background'`. `setLoginItemEnabled` only accepts `.app` paths. Real dumpbtm format (26.3): sections ` Records for UID <n> : <uuid>` (leading space, UIDs can be NEGATIVE — -2 = shared/system), records ` #N:`, a `Generation` field, and `Embedded Item Identifiers:` sub-lists whose `#N: value` lines must NOT match record headers; records repeat per UID section → dedupe prefers the current uid, then highest Generation (maintenance.ts `parseBtmDump`). sfltool can hang when invoked concurrently — the 15s timeout guards it.
- macOS TCC binds Automation consent to the code signature: with ad-hoc/dev-signed builds the consent is keyed per-build cdhash, so EVERY rebuild re-prompts (System Events for login items, Finder for trash). Only a stable Developer ID signature + notarization makes consent stick. Mitigations shipped: `GET /api/maintenance/login-items` is consent-free by default (BTM only); classic System Events list is opt-in via `?classic=1` (frontend "Show Open at Login apps" button); results cached 60s (`invalidateLoginItemsCache` on toggle); `NSAppleEventsUsageDescription` set in package.json extendInfo.
- The frontend is ONE file (`public/index.html`); JS binds by element id — never rename ids/data-* hooks. Any new raw `/api` URL (img/iframe/EventSource) must carry `?token=` — only `fetch` via `api()` gets the header automatically.
- Frontend STRINGS dicts: JS object-literal duplicate keys silently last-win — `quitFirst` was declared twice (browser vs app contexts) so the Privacy browser note showed the app string in ALL 5 languages; the browser occurrence is now `quitBrowserFirst`, the uninstaller one keeps `quitFirst`. Grep the dict before adding a key.
- Fans live paint (index.html): panes rebuild ONLY when `fanSignature()` changes (helperState/viewMode/boostSource/fan count/banner/sensor-set); an unchanged 3s poll tick must update values in place (`updateSensorsLive`/`updateFanCardsLive`/`updateControlLive`), and range sliders carry `data-dragging` (`bindDragGuard`, pointerdown/up/cancel) so `.value` writes skip mid-drag. Rebuilding innerHTML per tick kills slider drags.
- `DELETE /api/files` response is `{ deleted, failed, freedBytes, totalFreedBytes }` — always credit `totalFreedBytes` (server-confirmed), never a pre-measured listing size. `POST /api/privacy/browser-cache-plan` may answer 202 `{scanId,status}` → frontend `pollBrowserCacheScan` polls `GET /api/scan/:id/result` (90s cap) then re-requests the plan once; `browser-cache-credit` body is `{ id, bytes }` (catalog id).
- Scan TTL evictor: `diskScanner.setOnScanEvicted(fn)` is the seam (scanner can't import duplicateFinder — cycle), but the WIRING lives in duplicateFinder.ts itself (self-registers `cancelDuplicateJobsForScan` at module load, line ~75). server.ts deliberately does NOT re-wire — adding a second registration there would silently replace the first.
- Icon pipeline: edit `build/icon.svg`, rasterize with `swift scripts/render-icon.swift build/icon.svg 1024` → rename to `build/icon.png`; tray glyph is procedural — edit `inGlyph` in `scripts/gen-tray-icon.js` and run it. In-app marks (sidebar, empty state, favicon) are inline SVG in `public/index.html` — keep them in sync manually.
- UI verification on this machine is blocked at OS level: downloaded browser binaries (fresh Electron, Homebrew Chromium) get SIGKILLed on launch (security policy), `screencapture` lacks Screen Recording permission, Playwright's CDN download stalls, and `node_modules/electron/dist` keeps getting wiped (reinstall with `node node_modules/electron/install.js` when needed). Do NOT burn time fighting this — verify UI changes with user-provided screenshots.
